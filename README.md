# DSP Solver

`DSP Solver` 是《戴森球计划》的产线计算与配方求解工具。给定目标物品和每分钟产量，它会计算生产链所需的配方、建筑、原料和电力，并处理多产物配方带来的配平问题。

打开 [在线工作台](https://komonad.github.io/dsp-solver/)，选择游戏配置、添加生产目标，即可查看方案。调整配方、建筑或增产偏好后，工作台会自动重新求解。

## 功能

- 按占地、功耗或外部输入优化生产方案，支持强制配平和允许盈余
- 独立编辑原料、占地、功耗与产线复杂度权重，支持推荐预设和矿物稀缺度加权
- 先显示可用方案，再通过后台 MILP 持续优化配方种类，可随时停止并保留结果
- 指定原矿、允许或禁用配方、禁用建筑，以及全局或逐配方的建筑与增产偏好
- 查看配方用量、建筑数量、功耗、原料需求、冗余产物和物品收支
- 在交互式物品流图中追溯生产链，关注指定物品的上游，或将某段上游设为视图外供
- 保存多套产线配置，支持复制、命名、切换和编辑求解快照
- 加载自定义数据集，并通过运行时导出器采集游戏及模组的物品、配方和图标

## 内置数据集

| 预设 | 游戏 / 模组版本 |
| --- | --- |
| 原版 | 游戏 `0.10.35.29131` |
| 原版 + 四级增产剂 | 原版数据，追加四级增产剂物品、配方和喷涂规则 |
| 星环组合 | 游戏 `0.10.35.29131`；星环 `1.0.20` + 更多巨构 `2.0.1` + 深空来敌 `3.4.24` |

原版与星环组合的游戏数据均于 `2026-10-14` 从运行时核对更新。原版数据还包含用于计算的采集、充电等虚拟配方，以及建筑和增产参数。星环组合包含 356 个物品、367 条配方和 337 个物品图标，采用模组组合加载后的配方与建筑能耗。

模组组合的配方和可用建筑可能与原版不同。例如，星环组合中的黑雾引力透镜只允许使用物质重组工厂生产。自定义数据集可在工作台的“数据管理与自定义”中通过静态路径加载。

## 稀缺度与综合目标

内置预设会加载对应的资源抽样权重。原版与星环组合分别使用种子 `70289409`、`42481286`、`44102993`，按 64 星、1 倍资源生成星区并统计固体矿物。将各样本储量汇总后，以铁矿为基准计算反向丰度：`矿物权重 = 铁矿总量 / 该矿物总量`。气体和海洋资源默认权重为 0，未覆盖的原料默认为 1。抽样值只提供大致参考，所有资源权重均可手动修改。

工作台目标函数为 `(原料输入权重 × 加权原料输入/分钟 + 占地权重 × 连续建筑占地 + 功耗权重 × 工作功耗(MW)) / 产能倍率 + 产线复杂度权重 × 配方种类数`，其中产能倍率为总目标产量除以 60/分钟，总目标为零时取 1。

连续成本统一折算到总目标 60/分钟，多目标保持各自产量比例；所有目标等比例扩产时，成本与复杂度之间的取舍保持一致。例如，从 10/分钟扩产到 1000/分钟，无需调整复杂度权重。实际用料、占地和功耗按完整目标产能显示。同一配方的建筑和增产变体只计一种；占地考虑堆叠，不包含传送带、分拣器、布局间距及建筑数量向上取整。

推荐预设包括占地优先、功耗优先、原料优先、资源与占地平衡、精简产线。选择预设会填入一组权重，各项仍可独立编辑。“求解目标函数”可折叠，折叠后显示当前四项权重；悬停标题可查看公式和计价说明，悬停重置按钮可查看默认资源权重的来源。

配方卡片仅在有多个可用建筑时显示建筑选择胶囊。建筑、增产策略和增产等级均可再次点击已选项来取消指定；没有选中项时由全局设置和求解器决定。增产等级使用对应的增产剂图标，悬停可查看名称与等级；自定义数据缺少图标时显示等级数字。

复杂度系数大于 0 时，工作台先显示 LP 可行基线，再在 Worker 中持续进行 MILP 搜索并推送改进结果。后台搜索没有固定时长限制，默认在完整目标的最优性差距不超过 1% 时收敛；差距目标可手动设置，0 表示要求精确证明。停止优化会终止 Worker 并保留当前方案，修改目标或切换配置会取消过期搜索。“后台搜索”标题旁显示加载图标和本次用时，每次重新求解都会从零计时；折叠后继续搜索，保留配方种类、差距和停止入口。尚未证明精确最优的结果标为“可行方案”。

浏览器工作台与异步求解 API 默认使用 HiGHS，支持 LP 和 MILP。加权目标的盈余简化在数值容差内保留主目标成本。同步 API 保留 YALPS，以兼容不能等待 WebAssembly 初始化的调用方；也可传入已初始化的 HiGHS 实现。

## 本地开发

```bash
npm install
npm run build:all
npm run host
```

默认访问地址为 `http://localhost:8081`。开发时可运行 `npm run dev:web`；测试与类型检查分别使用 `npm test` 和 `npm run typecheck`。
